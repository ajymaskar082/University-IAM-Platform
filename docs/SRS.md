# SOFTWARE REQUIREMENTS SPECIFICATION (SRS)

# University IAM Platform

## 1. Жүйенің жалпы сипаттамасы

University IAM Platform — университеттің пайдаланушыларын сәйкестендіру, аутентификациялау және ақпараттық ресурстарға қол жеткізу құқықтарын орталықтандырылған түрде басқаруға арналған веб-жүйе.

Жүйе студенттерге, оқытушыларға және университет қызметкерлеріне бірыңғай аккаунт арқылы қауіпсіз қол жеткізуді қамтамасыз етеді.

## 2. Функционалдық талаптар

**FR-01. Пайдаланушыларды тіркеу**

Жүйе әкімшісі жаңа пайдаланушыларды тіркей алуы керек.

**FR-02. Аутентификация**

Пайдаланушы логин және пароль арқылы жүйеге кіре алуы керек.

**FR-03. Пароль қауіпсіздігі**

Парольдер BCrypt алгоритмі арқылы хэштеліп сақталуы керек.

**FR-04. Көп факторлы аутентификация**

Жүйе TOTP негізіндегі MFA механизмін қолдауы керек.

**FR-05. JWT токендері**

Жүйе Access Token және Refresh Token генерациялап, олардың жарамдылық мерзімін тексеруі керек.

**FR-06. Рөлдерді басқару**

Әкімші пайдаланушыларға рөл тағайындай, өзгерте және алып тастай алуы керек.

**FR-07. RBAC**

Жүйе пайдаланушының рөліне сәйкес рұқсаттарды тексеруі керек.

**FR-08. ABAC**

Жүйе факультет, бөлім, пайдаланушы мәртебесі және басқа атрибуттар бойынша қолжетімділікті шектеуі керек.

**FR-09. Аккаунт мәртебесін басқару**

Әкімші пайдаланушы аккаунтын белсенді, бұғатталған немесе өшірілген күйге ауыстыра алуы керек.

**FR-10. Автоматты бұғаттау**

Университеттен кеткен қызметкердің аккаунты бұғатталған кезде оның белсенді сессиялары мен токендері жарамсыз болуы керек.

**FR-11. Қате кіру әрекеттерін шектеу**

Жүйе қайталанатын қате кіру әрекеттерін анықтап, уақытша шектеу қоюы керек.

**FR-12. Audit Log**

Жүйе пайдаланушылардың кіру әрекеттерін, рөл өзгерістерін және әкімшілік операцияларды тіркеуі керек.

**FR-13. Әкімшілік панель**

Әкімші пайдаланушыларды, рөлдерді және қауіпсіздік параметрлерін веб-интерфейс арқылы басқара алуы керек.

**FR-14. Сессияларды басқару**

Пайдаланушы жүйеден шыққанда оның ағымдағы сессиясы жарамсыз болуы керек.

## 3. Функционалдық емес талаптар

**NFR-01. Қауіпсіздік:** парольдер ашық мәтін түрінде сақталмауы керек.

**NFR-02. Қолжетімділік:** жүйе тек аутентификациядан өткен пайдаланушыларға қорғалған ресурстарды ашуы керек.

**NFR-03. Сенімділік:** жүйе қате операциялар кезінде деректердің тұтастығын сақтауы керек.

**NFR-04. Өнімділік:** негізгі аутентификация және авторизация операциялары қалыпты жүктеме кезінде жылдам орындалуы керек.

**NFR-05. Масштабталу:** жүйенің архитектурасы жаңа пайдаланушылар мен рөлдерді қосуға мүмкіндік беруі керек.

**NFR-06. Қолдануға ыңғайлылық:** веб-интерфейс түсінікті және қарапайым болуы керек.

**NFR-07. Аудит:** маңызды операциялар журналда сақталуы керек.

## 4. Пайдаланушы рөлдері және құқықтары

| Рөл | Негізгі құқықтары |
|---|---|
| SUPER_ADMIN | Барлық жүйені және қауіпсіздік саясатын басқару |
| ADMIN | Пайдаланушылар мен рөлдерді басқару |
| STUDENT | Жеке профиль мен оқу ақпаратын қарау |
| TEACHER | Өз пәндері мен студенттердің бағаларын басқару |
| DEAN | Өз факультетінің ақпаратын басқару |
| HR_MANAGER | Қызметкерлердің мәртебесі мен аккаунттарын басқару |
| SECURITY_OFFICER | Қауіпсіздік оқиғалары мен Audit Log бақылау |

Әр рөлге тек өз қызметіне қажетті құқықтар беріледі. Факультет пен бөлімге байланысты қосымша шектеулер ABAC арқылы жүзеге асырылады.

## 5. Аутентификация және авторизация

Жүйеге кіру процесі келесі кезеңдерден тұрады:

1. Пайдаланушы логин мен пароль енгізеді.
2. Жүйе пайдаланушыны деректер базасынан іздейді.
3. Пароль BCrypt арқылы тексеріледі.
4. MFA қосылған болса, TOTP коды сұралады.
5. Пайдаланушының аккаунт мәртебесі тексеріледі.
6. Сәтті аутентификациядан кейін JWT токендері беріледі.
7. Қорғалған ресурстарға сұраныс кезінде рөлдер мен атрибуттар тексеріледі.

## 6. Қауіпсіздік талаптары

- Парольдер BCrypt арқылы хэштеледі.
- Қорғалған API ресурстары Spring Security арқылы бақыланады.
- JWT токендерінің қолтаңбасы мен жарамдылық мерзімі тексеріледі.
- Refresh Token жаңарту кезінде тексеріледі және қажет болғанда айналымға жіберіледі.
- MFA TOTP алгоритмі арқылы орындалады.
- Қате кіру әрекеттері шектеледі.
- Аккаунт бұғатталғанда белсенді токендер мен сессиялар жарамсыз етіледі.
- Құпия кілттер мен парольдер GitHub репозиторийіне енгізілмейді.
- Әкімшілік әрекеттер Audit Log журналында тіркеледі.

## 8. Жүйенің шектеулері

- Жүйе веб-платформа ретінде әзірленеді.
- Пайдаланушы құқықтары алдын ала анықталған рөлдер мен атрибуттарға негізделеді.
- Сыртқы университеттік ақпараттық жүйелермен интеграция осы жобаның бастапқы нұсқасына кірмейді.
- Жүйе PostgreSQL деректер базасын қолданады.
- MFA үшін пайдаланушыға TOTP қолдайтын аутентификатор қажет.

## 9. Қабылдау критерийлері

Жоба төмендегі шарттар орындалғанда дайын деп есептеледі:

1. Пайдаланушыларды тіркеу және жүйеге кіру жұмыс істеуі керек.
2. BCrypt парольдерді дұрыс тексеруі керек.
3. TOTP арқылы MFA жұмыс істеуі керек.
4. JWT Access және Refresh Token механизмдері іске асырылуы керек.
5. Жеті рөл бойынша авторизация дұрыс жұмыс істеуі керек.
6. RBAC және ABAC тексерістері орындалуы керек.
7. Бұғатталған аккаунт жүйеге кіре алмауы керек.
8. Audit Log маңызды операцияларды тіркеуі керек.
9. Кемінде 20 JUnit тест сәтті орындалуы керек.
10. GitHub Actions арқылы автоматты тестілеу орындалуы керек.
